## Where things live

- `runGates` composes the four gates in spec §8 order. Call it rather than
  sequencing `lintSpec` / `diffSpecs` / `assertNoDbImport` again; the order is a
  governance decision, not a convenience.
- `runGates` populates `report.document` ONLY when handed a `contract`. Given a
  `specPath` it leaves it null, so an assertion reading it is vacuous. Read the
  emitted bytes instead.
- Each contract package's `scripts/emit.ts` exports `buildDocument()` and
  `serializeDocument()`. That pair is the seam anything re-emitting should use.
- `scripts/contractPackages.ts` is the single list of contract packages and
  consumers. A second hand-maintained list is how a new package escapes a gate.
- `packages/db` exports `.`, `./seed`, `./testing` and `./migrate`. The testing
  subpath stands up a throwaway Postgres; it is deliberately not re-exported
  from the package barrel, because importing the barrel must not need a server.
- `services/service-a/src/main.ts` is the process entrypoint; `src/index.ts` is
  a side-effect-free barrel and starts nothing.

## Repo-specific gotchas not yet promoted

- `api_usage` inverts the column-naming rule the rest of the schema follows.
  That is deliberate — do not "fix" it.
- The seed is deliberately non-uniform: 57 transactions, 540000 of 1000000 SEK
  minor units remaining, so the dashboard reads `5 400/10 000 kr` and
  `54 more items`. Those figures are asserted against `assets/mobile-view.png`
  and are load-bearing for the demo.
- The card art base URL must be an ORIGIN. `artAssetKey` already carries its own
  `card-art/` prefix, so a base ending in `/card-art` emits a doubled segment.
  No gate catches it — the URL is still a valid `format: uri` string.
- Drizzle names every column in an INSERT, so a column-name assertion over an
  insert is near-vacuous. Assert the generated DDL, or read a row back.
- An uncast `SUM()` comes back from `pg` as a STRING. A naive numeric assertion
  hides it.
- `drizzle`'s `count()` returns a number, but not because the SQL says so.
- Declare drizzle indexes ASCENDING even when every read sorts newest first.
- `newline-per-chained-call` breaks every Drizzle column builder; expect to run
  `eslint --fix` after writing schema modules.
- You cannot write an ANSI-stripping regex literal in this repo — the control
  byte gate rejects the literal ESC. Build it from its code point.
- `TsRestRequest` is not an Express `Request`; only `IncomingMessage` is shared.
- Per-request context hangs on a `WeakMap`, not on an augmented `Request`.

## Open debt

Six plan tasks remain unbuilt. None blocks the demo; all are recorded so the
next run does not rediscover them.

- `services/service-b` has a client for `service-a` but no routes and no
  server, so it is a consumer in fact and a provider only on paper. Its
  due-invoice operation is declared in `contracts-service-b` and answered by
  nothing.
- No integration test for that endpoint, for the same reason.
- `scripts/pipeline-simulation.ts` has no test of its own. The acceptance
  scripts cover the gates it runs, but not its own reporting — a change that
  broke its output formatting would be invisible.
- No test asserting the five acceptance scripts exit with the codes they claim.
  Each is verified by hand and in CI, but nothing would catch one that silently
  stopped asserting.
- `docs/breaking-changes.md` (spec §6.2 major-version procedure) and
  `docs/field-retirement.md` (spec §6.4) are unwritten. `docs/governance.md`
  covers both at lower resolution.

Resolved differently from the plan, not missing:

- The CI publish step landed as `contracts:publish` plus the version gate rather
  than a push on merge. Writing to `main` needs `contents: write` on a public
  repo and fights branch protection; a committed baseline is reviewable in the
  diff that changes it.
